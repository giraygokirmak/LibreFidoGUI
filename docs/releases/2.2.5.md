LibreFido 2.2.5: the tools install the GUI by default.

`librefido_tools` now depends on PySide6 (PySide6-Essentials: the Qt core
modules the GUI uses), so `librefido-gui` starts after a plain install (#6).
The `[gui]` extra still works. The firmware is the same
as 2.2.4 apart from its version number.

| Hardware | Image for initial flashing at `0x0` | Layout / button |
| --- | --- | --- |
| ESP32-S3 N16R8 / compatible 16 MB boards | `librefido-2.2.5-esp32s3-standard-full.bin` | 16 MB / GPIO0 |
| M5Stack AtomS3U | `librefido-2.2.5-atoms3u-4mb-standard-full.bin` | 4 MB layout / GPIO41 |
| Other 4 MB boards (e.g. Waveshare ESP32-S3-Zero) | `librefido-2.2.5-esp32s3-4mb-standard-full.bin` | 4 MB / GPIO0 |

The generic 4 MB image keeps GPIO0 for the BOOT button, including on the
Waveshare ESP32-S3-Zero. Do not use the AtomS3U image on other boards: its
button is GPIO41 and will not respond. On the S3-Zero, the WS2812 status LED
is GPIO21; set it once with `librefido board --led-gpio 21`, then replug.

The 4 MB layout has one profile and 256 KiB of key storage. Its application
images update only another `esp32s3-4mb` installation, never a 16 MB one.

```bash
python -m pip install librefido_tools-2.2.5-py3-none-any.whl
```

Validation: the tools tests (with cryptography 41 and the current one) and
the wheel's dependencies. Firmware builds use ESP-IDF 5.5.1. The packager
checks each image's version, platform, button GPIO, flash size, partition
bounds, OTA slot sizes and merged full-image content. The AtomS3U image was
confirmed on the device in #3 with 2.2.4; 2.2.5 firmware differs only in its
version number. ESP32-S3-Zero hardware testing has not been performed.

`SHA256SUMS` covers the release assets. An OpenPGP signature is not attached.
